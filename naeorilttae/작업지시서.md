# 작업지시서 — 나어릴때 제안서 PPT 제작 (Claude Code용)

---

## 0. 사용 방법 (김현수 팀장용)

1. 아래 **폴더 구조** 그대로 폴더를 만들고 파일을 넣습니다.
2. 그 폴더에서 Claude Code를 엽니다.
3. 이렇게 입력합니다: **`작업지시서.md 읽고 1단계부터 진행해줘`**
4. 1단계가 끝나면 Claude Code가 "레이아웃 매핑표"를 보여주고 멈춥니다. 확인 후 **`진행해`**라고 하면 끝까지 만듭니다.
5. 결과물은 `output/` 폴더에 생깁니다.

---

## 1. 목표

`나어릴때_제안서_원고.md`(32장)를 `template/template.pptx`의 디자인으로 PPT로 만든다.

- 템플릿의 레이아웃, 폰트, 색상을 그대로 사용한다. 새 디자인을 만들지 않는다.
- `refs/` 폴더의 레퍼런스는 **레이아웃 구성과 정보 배치 방식만** 참고한다.
- 결과물은 사람이 PowerPoint에서 바로 수정할 수 있어야 한다. 텍스트는 텍스트 상자로, 차트는 네이티브 차트로, 표는 네이티브 표로 만든다. 텍스트를 이미지로 넣지 않는다.

## 2. 폴더 구조

```
naeorilttae_deck/
├─ 작업지시서.md                 ← 이 파일
├─ 나어릴때_제안서_원고.md        ← 슬라이드 원고 (S01~S32)
├─ template/
│   └─ template.pptx             ← 팀장님이 만든 템플릿
├─ refs/                          ← 레퍼런스 (PDF, PNG, PPTX 아무거나)
├─ assets/                        ← 캡처·이미지·데이터 (파일명 규칙은 5장 참고)
└─ output/                        ← 결과물 (Claude Code가 생성)
```

## 3. 템플릿 제작 가이드 (팀장님이 템플릿 만들 때 참고)

`template.pptx`의 **슬라이드 마스터 > 레이아웃**에 아래 레이아웃이 있으면 결과가 가장 좋습니다.
레이아웃 이름은 아래 영문 이름 그대로 지정해 주세요. 없는 레이아웃은 Claude Code가 가장 가까운 레이아웃에 도형을 추가해 만듭니다.

| 레이아웃 이름 | 용도 | 필요한 개체 틀 |
|---|---|---|
| cover | 표지 | 제목, 부제, 본문(날짜·귀중), 로고 그림 |
| toc | 목차 | 제목, 본문 |
| section | 간지 | 섹션 번호, 제목, 부제 |
| content | 기본 본문 | 상단 섹션 라벨, 제목(헤드라인), 부제, 본문 영역, 출처 |
| two-column | 좌우 2단 | content + 좌·우 본문 |
| image-text | 이미지 + 설명 | content + 그림 개체 틀 1~2개 |
| closing | 마무리 | 제목, 본문, 로고 |

- **최소 필수: cover, section, content** 3개. 나머지는 content를 응용해서 만들 수 있습니다.
- 색상은 테마 색(디자인 > 변형 > 색)에 지정해 두면 Claude Code가 그 색만 씁니다.
- 폰트도 테마 글꼴로 지정해 주세요 (예: Pretendard).
- 샘플 슬라이드를 1~2장 만들어 두면, Claude Code가 그 여백과 글자 크기를 기준으로 맞춥니다.

## 4. 원고 파일 읽는 법

- `## S00 | 이름` 하나가 슬라이드 하나다.
- 각 항목의 의미:

| 항목 | 의미 |
|---|---|
| layout | 원고 작성자가 의도한 구성. 템플릿 레이아웃 이름이 아니라 **배치 의도**다 (예: cards-3 = 카드 3개 가로 배치). 1단계에서 템플릿 레이아웃에 매핑한다 |
| section | 상단 섹션 라벨 (예: 02 사전 진단) |
| headline | 슬라이드 제목. 결론형 문장이다. 줄이지 말고 그대로 쓴다 |
| sub | 부제. 출처·기간·조건을 담는다 |
| body | 본문. 들여쓰기 단계를 위계로 사용한다 |
| data | 차트·표 데이터. 반드시 네이티브 차트·표로 만든다 |
| image | `assets/`의 파일명 |
| source | 슬라이드 하단 출처 (작은 글씨) |
| note | 발표자 노트에 넣는다. 슬라이드에는 표시하지 않는다 |

- `〔확인〕` 표시가 있는 텍스트는 **노란 배경 하이라이트**로 표시한다. 내용은 바꾸지 않는다.

## 6. 작업 단계

### 1단계 — 분석 (끝나면 멈추고 보고)

1. `template.pptx`를 열어 슬라이드 마스터의 레이아웃 목록, 각 레이아웃의 개체 틀 이름·위치·크기, 테마 색상, 테마 폰트를 정리한다.
2. 템플릿에 샘플 슬라이드가 있으면 여백, 제목·본문 글자 크기, 정렬 기준을 추출한다.
3. `refs/`의 레퍼런스를 보고 참고할 점을 3~5줄로 요약한다 (레이아웃 구성, 정보 밀도, 강조 방식).
4. 원고 S01~S32의 `layout`을 템플릿 레이아웃에 매핑한 표를 만든다.

| 슬라이드 | 원고 layout | 사용할 템플릿 레이아웃 | 추가로 그릴 도형 |
|---|---|---|---|

5. `assets/`에서 없는 파일 목록을 정리한다.
6. 위 내용을 보고하고 **사용자 확인을 기다린다.**

### 2단계 — 제작

1. `python-pptx`로 `template.pptx`를 열어 그 위에 슬라이드를 추가한다. 템플릿의 기존 샘플 슬라이드는 최종 파일에서 삭제한다.
2. 슬라이드마다 매핑된 레이아웃을 쓰고, 개체 틀에 텍스트를 넣는다.
3. 카드, 화살표, 타임라인, 프로세스, 큰 숫자 같은 구성은 테마 색만 써서 도형으로 그린다.
4. `data` 항목은 네이티브 차트·표로 만든다.
   - S09: 도넛 차트 2개
   - S10: 가로 막대 차트 1개 + 꺾은선 차트 1개 (원고의 월별 수치 사용, CSV로 검산)
   - S12, S19, S31: 표
5. `note`는 발표자 노트에 넣는다.
6. 저장: `output/나어릴때_제안서_v1.pptx`

### 3단계 — 검수

1. LibreOffice로 PDF 변환 후 슬라이드별 PNG로 만든다 (`output/_qa/`).
2. PNG를 한 장씩 직접 보고 아래를 확인하고 고친다.
   - 글자가 상자 밖으로 넘치지 않는가
   - 요소끼리 겹치지 않는가
   - 빈 개체 틀("텍스트를 입력하십시오")이 남아 있지 않은가
   - 좌우 여백과 정렬이 슬라이드끼리 일정한가
   - 원고의 수치가 빠짐없이, 틀림없이 들어갔는가
3. 고친 뒤 다시 변환해 확인한다. 문제가 없을 때까지 반복한다.
4. `output/QA.md`에 결과를 남긴다.
   - 슬라이드별 상태 (OK / 수정함 / 확인 필요)
   - 없는 이미지 목록
   - `〔확인〕` 항목 목록
   - 원고와 다르게 처리한 부분과 이유

## 7. 텍스트 규칙

- 헤드라인은 원고 그대로 쓴다. 넘치면 글자 크기를 줄이되, 템플릿 제목 크기의 80% 미만으로는 줄이지 않는다. 그래도 넘치면 2줄로 바꾸고 QA.md에 기록한다.
- 본문은 원고의 문장을 임의로 요약하거나 바꾸지 않는다. 공간이 부족하면 하위 항목의 글자 크기를 먼저 줄이고, 최소 크기(12pt) 아래로는 줄이지 않는다. 그래도 넘치면 QA.md에 기록하고 사용자 판단을 받는다.
- 한글은 단어 중간에서 줄이 바뀌지 않게 한다 (줄바꿈 위치를 직접 조정).
- 수치·단위·날짜 표기는 원고와 똑같이 쓴다.

---

## 8. 금지 사항

- 원고에 없는 수치, 사례, 고객사명을 만들어 넣지 않는다.
- 인스타그램 운영에 협력사·외주를 언급하지 않는다 (NICECORE 운영으로 표기).
- '자체 개발 프로그램', '자체 솔루션' 같은 표현을 쓰지 않는다.
- 경쟁사 로고를 그려 넣거나 재현하지 않는다. 경쟁사는 텍스트와 원고에 지정된 캡처로만 표현한다.
- 레퍼런스의 문구, 로고, 이미지를 결과물에 복사하지 않는다.
- 템플릿에 없는 폰트·색상을 새로 쓰지 않는다.
